# 藝術設計部專案管理系統 · 系統規格書

> 版本對應 commit：`190fd03`（2026-06）· 線上：https://artdesign.zeabur.app/

本文件描述系統的**業務規則與行為規格**。技術架構見 [architecture.md](./architecture.md)，操作說明見 [features.md](./features.md)。

---

## 1. 系統定位

供連鎖飯店集團「藝術設計部」使用的內部專案（設計案件）管理系統。涵蓋：案件建立與派工、進度追蹤、確稿/結案審核流程、設計師工作量與貢獻分析、休假／出差／拍攝行程排程，以及甘特圖／看板等多種檢視。

## 2. 角色與權限

| 角色 | 說明 | 主要權限 |
|------|------|----------|
| **admin**（管理者，如 Mark） | 設計主管 | 全部案件可編輯、審核中心通過/退回、人員管理、離職移轉、可「切換到成員視角」檢視 |
| **member**（設計師） | 一般同仁 | 建立案件、編輯**自己主負責**的案件、對自己參與（主負責或協作）的案件寫子項目與進度日誌、休假/出差/拍攝登錄 |

權限要點：
- 案件 PATCH：僅 **admin 或主負責人**。協作者可讀、可寫子項目與進度日誌，但不可改案件主欄位。
- 結案（`closed`）：member 不可直接設定，需經 admin 在審核中心通過。
- 拍攝行程：任何登入者可建立；編輯/刪除限**建立者或 admin**。
- 休假/出差：僅能登錄**自己的**（admin 例外）。

## 3. 核心資料概念

- **案件（Case）**：一個設計專案。ID 格式 `{分級}-{YYYY}-{MM}-{序號3碼}`，例 `A-2026-06-001`。
- **子案件 / 執行項目（items）**：一個案件下的多個製作物工項，存於案件的 JSON 欄位；每筆有名稱、製作物類型、負責人、起訖日、狀態（可同時 2 個）、與**子項目日誌**。
- **製作物項目（deliverables）**：案件層級的多選標籤（電子看板／PDF／GIF／印刷輸出／官網／拍攝…）。
- **進度日誌（logs）**：案件層級的時間軸記錄；可自選日期、逐筆編輯/刪除。
- **館別（Hotel）／需求單位（RequestUnit）**：字典資料，admin 可維護。

## 4. 案件狀態機

主案狀態（`status`）：

```
尚未開始 todo → 等待中 wait → 進行中 doing → 確稿中 review
        → 確稿完成 review_done →（admin 審核）→ 已結案 closed
        ↘ 送印中 print（選填階段，印刷案件適用）
```

- `done`：舊版「已完成」，與 `closed` 視覺等同，僅為歷史相容。
- **看板**顯示非終態 6 欄：尚未開始／等待中／進行中／確稿中／確稿完成／送印中。終態（closed/done）自動歸檔、不在看板。
- **看板拖曳**：卡片拖到他欄即改狀態（admin 或主負責人）。拖到「確稿完成」需先填檔案歸檔位置，否則引導至卡片操作。
- **審核流程**：設計師將案件推到 `review_done` → 系統通知所有 admin → admin 在審核中心「通過」→ 自動設為 `closed` + 歸檔 + 通知設計師；「退回」→ 回 `doing` + 附意見通知。

## 5. 關鍵日期規則

以**台灣行政院人事行政總處公布之國定假日**計算工作天（週末＋國定假日不計）。

| 日期 | 規則 |
|------|------|
| 上線日（goLiveDate） | 必填，案件交付日（deadline） |
| 確稿日（reviewDate） | = 上線日 − 3 個工作天（系統自動推算） |
| 校稿日起（proofStart） | = 確稿日 − 2 個工作天（自動推算） |
| 需求派發日（dispatchDate） | 必填 |
| 文案收件日（copyDate） | 選填 |
| 印刷送印日（printDate） | 選填；**建議 ≥ 上線日前 5 個工作天**，不足則軟警示（不阻擋） |
| 需發包（needsOutsourcing） | 勾選；建議預留 7–10 個工作天，建議發包日 = 上線日 − 10 工作天 |

**待簽核提醒（gateActive）**：確稿日剩 ≤ 3 個工作天且未提出確稿時觸發，卡片顯示紅色待簽核標記、通知 admin。已進入 review/review_done/print/終態者不再觸發。

## 6. 工作量與分析

**分級權重**：SS=5、S=4、A=3、B=2、C=1、D=1。

- **工作量分數** = Σ(分級權重 × 件數)；主負責 ×1.0、協作者 ×0.4。僅計**未結案、未封存**案件（排除 done/closed）。超載門檻：≥ 10 分。
- **繼承者建議**（離職移轉）：工作量最低者優先；SS/S 級案若工作量相同，改以資深同仁優先。
- **貢獻分析**：僅計已完成（done/closed）且 `closedOn` 落在統計期間者。計分 = 分級權重 × 角色係數 × 準時係數 × 急件係數。準時係數：提早(closedOn ≤ 上線日−1日)＝×1.1、準時＝×1.0、逾期＝×0.8；急件 ×1.3。

## 7. 通知規則（Email）

- **建立案件**：由建立者勾選「通知負責人／通知協作者」決定是否寄送（**預設不寄**，避免信箱轟炸）。
- **推到確稿完成**：自動通知所有 admin。
- **審核通過/退回**：通知設計師。
- **admin 代為修改他人案件**：通知該案主負責人（含變更明細）。
- 實際是否寄出取決於 SMTP 環境變數（`SMTP_HOST/USER/PASS/FROM`）是否設定；未設定則為示意。

## 8. 排程模組（獨立於案件）

| 模組 | 綁定 | 欄位 | 顯示 |
|------|------|------|------|
| **休假** | 個人（staffId） | 類型/起訖/備註 | 甘特上方「同仁休假/出差」、看板 |
| **出差** | 個人（staffId） | 起訖/館別/任務/備註 | 同上 |
| **拍攝** | 部門共享（不綁人） | 內容說明/外發vs自拍/起訖/攝影師/地點/備註 | 甘特上方「拍攝行程（未來 60 天）」 |

三者皆透過右下角浮動鈕（FAB）或對應 topbar 入口開啟管理介面。

## 9. 非功能規格

- **資料持久化**：所有使用者輸入（案件、子項目、日誌、拍攝等）即時寫入 PostgreSQL，跨容器重啟保留。`seed` 僅在空資料庫時灌入範例。
- **稽核**：時程/狀態/負責人/分級/急件等「受追蹤欄位」變更會寫入 ChangeLog（含原因，原因選填）。
- **安全**：JWT cookie 驗證、helmet CSP、登入限流、bcrypt 密碼雜湊。
- **主題**：Glassmorphism × 四季自動配色 × 日/夜模式；字體 LINE Seed Sans（拉丁）+ LINE Seed TW / Chiron Hei HK（中文）。
